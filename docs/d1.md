# D1 第一阶段：规则、采集资料与完整支护模板

本阶段实现 A01、A02、A03 和 A08 的决策资料维护部分。使用说明书与[实施方案](算法与功能实施方案.md)作为依据；用户已授权先构建规则算法，并使用合成资料测试。当前没有真实工程资料、训练模型或工程控制判据。

## 本地启动

```bash
pnpm install
pnpm backend:install
pnpm dev:d1
```

访问 `http://localhost:5000/decision`。继续使用现有 Python，不创建虚拟环境。

启动时先启动 Next.js 并预热内部决策资料接口，资料可读取后才启动 Python；首次编译或本地数据库初始化较慢时请等待“决策资料已就绪”。这避免内部资料接口冷启动超过 Python 的请求超时。开发资源允许本地地址及当前 Codespaces 的转发域名访问。8000 是 Python API 端口，网页请访问 5000；直接访问 Python 的 `/` 返回 404 属正常现象。

`dev:d1` 显式使用隔离 PGlite，初始化 `.local/decision-test`。所有初始规则、模板与采集场景标为 `simulation`，批次为 `d1_synthetic_v1`。它不会连接或写入 Supabase。重复启动保留已有内容和启停状态，不覆盖手工创建的新版本。

正常数据库模式使用 `pnpm dev:all`，按 `.env.example` 配置 Supabase 并执行全部迁移。没有连接配置时返回明确提示，不自动改用测试资料。旧的 `db:seed` 只初始化原基础资料，不会把自由文本映射自动发布成可执行规则。

联合启动会生成共享的内部资料密钥。分开启动服务时，Next.js 和 Python 需要配置相同 `DECISION_CATALOG_API_KEY`，以及指向 Next.js 的 `DECISION_CATALOG_URL`。密钥不应使用 `NEXT_PUBLIC_` 前缀。

## 建议先按这个顺序试用

1. 打开智能决策中心，选择“临时测试主洞工作面”和 `K3601+200`，点击“同步数据”。埋深应为 620 m，并显示测试来源与采集时间。
2. 点击启动推理，查看台阶法及规则命中理由。确认工法后，得到四类完整构件规格。
3. 修改锚杆长度等开放数值。旧结果失效，报告按钮禁用；点击重新检查后可生成“待复核配置报告”。当前评价为无法评价，不会生成安全分数。
4. 保存到台账，刷新 `/scheme`，展开记录并查看保存报告。配置、来源与版本保留在快照中。
5. 在经验数据库的标准工法库中找到“可执行工法与支护映射规则”，停用 `test_method_iv`。新一轮匹配不再自动推荐台阶法；可以恢复启用再验证。
6. 在支护体系页查看完整模板。新增版本不会覆盖旧内容；启用新模板版本时，也需要发布引用该版本的支护映射规则。可用一次批量导入原子发布模板与规则。

## 维护与版本

- 工法/支护规则支持类别相等、允许值集合、明确端点的数值区间，以及排除条件。先确认规则适用条件，再处理该规则的排除项；排除优先于其他命中推荐。
- 同一工法汇总规则依据，按最高优先级排序。不同工法同优先级并列；无匹配时人工确认需填写理由；硬性排除不能靠人工理由覆盖。
- 完整支护模板包括钢架、喷层、锚杆和超前支护的全部已定义规格。旧字符串资料没有自动补造直径、材料或间距，不能直接作为已完成模板使用。
- 规则与模板的编码/版本内容不可覆盖；“新版本”复制后增加版本号。启用某版本会停用同编码的其他版本。
- 批量导入先做结构校验，保存时在事务中验证引用。任何错误整批回滚；重复导入不覆盖既有启停状态。
- 导出格式为 `formatVersion: 1` 的 JSON，支持重新导入。“仅校验”不写数据库，也不代替保存时的引用完整性验证。
- “重置查询”只影响筛选，不删除资料。采集记录按不可变 ID 保存；更正应新增记录，保留来源和时间。

算法通过 capabilities 声明部分输入、模板选择与同步能力；页面不根据算法名称判断这些能力，便于替换实现。

每个计算请求读取数据库的一份一致性快照，内容摘要进入算法版本。推理后的后续步骤和保存若发现资料改变，会返回 409，要求重新匹配；不会悄悄使用新版本替换旧结果。历史查询只读保存快照，不重新运行当前规则。

## 本阶段的范围边界

响应预测、工程安全判据、承载验算、装备能力估算与数据库总览统计仍待后续阶段。D1 不把旧评分、固定成拱参数或雷达图当作新结果展示。原自由文本知识映射、旧支护列表及装备列表仍保留原功能入口；新增可执行资料由上方维护区负责，不会自动把两类资料相互解释。

实际 Supabase 迁移、PostgREST、RLS 和网络尚需有测试实例后验证。本地 SQL 和浏览器测试能证明本地软件链路，不证明工程预测精度或施工安全。

## 删除测试台账

更新代码后重新启动 `pnpm dev:d1`，会自动追加执行迁移 `007_delete_scheme_history.sql`。进入“方案报告与决策台账”：

- 单条记录右侧点击“删除”，核对确认框中的记录、工作面与里程，点击“确认删除”。取消不会修改数据。
- 本地测试模式右上角提供“清空测试记录”。它清理整个本地测试库的台账，不受当前页面筛选影响；需要输入“清空测试记录”再确认。
- 删除包含关联报告和不再被其他记录引用的决策快照，无法恢复。规则、完整模板、采集记录、工作面等基础资料保留。刷新后记录不会回来，重新决策可以再次保存。
- 清空入口仅适用于隔离本地测试模式；正式数据库接口拒绝该清空请求。正式库单条删除需先显式执行新增迁移。未配置数据库时展示的内置演示台账不提供删除按钮。

删除为用户在页面确认后执行；代码更新与自动测试不会清空你的 `.local/decision-test` 台账。浏览器删除测试只操作独立 `.local/d1-browser`。

### Python 端口占用与退出

联合启动会先检查 `BACKEND_PORT`（默认 8000）。如已占用，先停止旧服务再启动；也可临时使用 `BACKEND_PORT=8001 pnpm dev:d1`，网页端口仍为 5000。如果你另行配置了 `DECISION_BACKEND_URL`，其端口也需对应修改。

退出时在运行终端按 Ctrl+C，等待命令提示符返回。启动脚本向整个服务进程组发送退出信号，等待释放端口；超过 5 秒仍未退出的本次服务进程组会被终止，避免重载进程残留。该清理仅针对本次启动的子进程，不按端口随意终止其他 Python 服务。
