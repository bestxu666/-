## 实际页面验收

1. 同步采集记录 → 工法推荐 → 完整支护模板 → 修改锚杆长度 → 重新检查 → 生成报告 → 保存 → 刷新台账 → 打开历史报告；保存结果保留修改值，评价分数为空。
2. 同时刻冲突、采集缺项与无记录分别显示对应状态，不沿用旧位置数据。
3. 同优先级推荐等待人工选择；命中硬排除的工法不可选。
4. 页面启停规则会改变新一轮推荐；无效导入保留错误信息且不写入数据库。
5. 缺失参数不作为零发送；只提供规则所需条件仍可匹配相应模板。
6. 规则预览不落库；发布新规则版本后后端采用新内容。
7. 完整模板表单保存新规格，发布关联规则后算法实际采用新模板。

## 本次结论与限制

规则匹配、资料维护、数据库读取、页面交互及报告历史闭环在本地通过。四构件完整规格按模板返回；没有响应模型与工程判据时显示“无法评价”，不生成安全分数、置信度或成拱参数。D2—D4 的响应预测、承载验算、装备能力与真实工程验证尚未完成。

本次未验证实际 Supabase 实例的迁移、PostgREST、RLS 和网络行为。合成场景证明软件按已定义规则运行，不证明规则具有工程适用性或施工安全性。后续可替换数据库规则和模板；新增计算模型通过算法协议与工厂接入，详见 [D1 说明](d1.md)与[后端说明](backend.md)。
