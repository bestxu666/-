# D2：响应计算与变形评价

对应实施方案 A04/A05，以及 A07 的调整对比和评价快照。当前交付可执行的测试响应算术、判据比较和完整页面链路；没有训练模型或真实工程控制值。

## 在网页中体验

先 Ctrl+C 停止旧服务，等待命令提示符返回，然后执行：

```bash
pnpm dev:d2
```

打开 5000 端口的 `/decision`。继续使用已有 Python，不创建虚拟环境，不需新增模型依赖。D2 默认在 `.local/decision-d2-test` 保存独立测试数据，初始化 D1 的规则与模板和 D2 的四条判据版本记录，不写 Supabase；原 D1 台账不搬入 D2 测试库。终端显式设置 `DECISION_LOCAL_TEST_PATH` 可使用另一测试目录。

1. 保持评价阶段“初支完成后”、位移基准“自开挖起增量”；断面标识可保留默认值。
2. 选择临时测试主洞工作面与 `K3601+200`，同步数据，启动推理，确认台阶法并读取支护模板。
3. 初始测试沉降 **8 mm**、收敛 **6 mm**；测试上限分别 **10 mm**、**8 mm**，显示“临时测试 · 该范围内满足”。
4. 钢架间距改为 **160 cm**，点击“重新检查当前配置”。沉降 **10 mm**、收敛 **7.5 mm**，边界满足。
5. 钢架间距改为 **240 cm**再检查。沉降 **12 mm**、收敛 **9 mm**，显示“不满足”；初始值仍为 8/6，图表可比较初始、当前与控制值。
6. 生成待复核报告、保存台账，刷新 `/scheme` 并展开查看报告。历史明细和图表使用保存时快照。

这些间距、公式和限值都是软件测试场景，不是施工选型建议。“该范围内满足”仅指这两项已配置的变形检查，不包含支护承载或整体安全结论。

其他可复现情形：

| 操作 | 结果 |
|---|---|
| 初始配置将锚杆由 3 改为 6 m | 重算沉降 7 mm、收敛 5.25 mm |
| 将埋深改为 900 m，重新匹配并人工选台阶法 | 合成场景缺收敛，显示“—”和无法评价 |
| 在 900 m 场景将钢架改为 240 cm | 沉降不满足，同时保留收敛缺项；总体不满足 |
| 将锚杆改为 8 m | 页面合法输入，但超出测试模型适用范围，返回无法预测，不外推 |
| 阶段选“开挖后”或基准选“总位移” | 原结果失效；重新决策后明确显示模型未覆盖 |
| 模型未接入、调用失败或超时 | 返回原因，不回退模拟结果或继续展示旧响应 |

## 判据维护

在 `/knowledge` 的“支护体系与参数库”找到“变形评价判据”。支持查询、刷新、新增版本、启用与停用；完整 JSON 可编辑指标、单位、适用断面类型、阶段、位移基准、上下限、必需性和依据。当前指标仅沉降与收敛，单位只接受 mm；不默默转换不同单位。

- 比较支持 `<=`、`>=`、闭区间 `range`。`<=` 仅填 upper，`>=` 仅填 lower，区间两端都填且 lower ≤ upper。
- 相同编码/版本内容不能覆盖；启用新版本会停用同编码旧版本。重复初始化不覆盖用户启停状态或新版本。
- 测试资料 source 为 simulation，并带 testBatchId。正式判据只能由有来源的资料维护，不把合成限值标成工程标准。
- 两个不同编码同时适用于同一指标时报告冲突，不任意选一个。当前范围包括沉降和收敛；缺少某指标有效判据时列为必需缺项，不把停用判据视为免检。
- 首批 v1 上限为 10/8；停用的 v2 上限为 7/5。启用 v2 后，新一轮初始 8/6 会不满足。
- 资料更改后进行中的任务返回 409，要求重新匹配；旧报告不随新版本重算。保存失败保留填写内容。

| `backend/app/response_models.py` | 响应、口径和判据契约 |
| `src/lib/response.ts` | TypeScript/Zod 契约与判据格式化 |

| `src/storage/database/migrations/008_deformation_criteria.sql` | 第 15 张业务表、发布与启停事务、一致快照及台账评价状态保存 |
| `src/data/d2-fixtures.ts` | 明确标为合成的两指标两版本判据 |
| `tests/fixtures/d2-response-cases.json` | 24 组独立预先列出的四构件调整期望值 |

接入真实模型时，实现 `ResponseProvider.info` 和 `predict(request, method_key, support)`，以 `DECISION_RESPONSE_FACTORY=your.module:create_provider` 配置。工法和完整支护推荐仍由 configurable 组合，页面不需要重新实现预测逻辑。`support` 是当前四类构件的完整结构，不只四个微调值；request 带工程参数、工作面、里程、评价断面、阶段和位移基准。

返回值需符合 ResponseResult，携带相同输入摘要、口径、明确单位与模型版本。真实提供器 `isTest=false`、source=model；错误、缺输入和超范围返回不可用及原因。远程适配器应设置自身网络/计算超时，保证 predict 有限时间退出；外层默认等 5 秒，最多 4 个任务，繁忙时直接返回不可用。外层超时不意味着可强制中断正在执行的 Python 线程，所以适配器自己的超时不可省略。

测试实现仅在 `DECISION_ALLOW_TEST_RESPONSES=true` 且 `DECISION_DATA_SOURCE=local-test` 时允许加载；`dev:d2` 自动配置。`dev:d1` 明确关闭测试响应，`dev:all` 默认模型未接入，均不会因缺数据自动回退合成预测。真实模型上线前还需真实样本、适用范围与独立误差验证，参照实施方案 D4。

## 版本与评价语义

模型/manifest 内容摘要和判据内容进入算法版本；后续计算及保存固定本轮版本。判据数据库读取与规则、模板、采集资料处于同一 SQL 快照。算法状态、测试来源和传输通道分开保存；服务端生成 isTest，Python 同源服务记为 real 通道不代表工程结果真实有效。报告 schemaVersion 为 3，保存最终及当前所选工法原始推荐的初始评价、完整响应、判据、输入口径、模型版本、测试批次与摘要；旧版没有这些字段的报告继续兼容。

任一必需项已知不满足则总体不满足，并保留其他缺项；无必需项或缺少任何必需结果/有效判据则无法评价；全部必需项满足才在该范围内满足。无评分、雷达图、承载验算或成拱参数。参数或口径修改后旧结果清除，必须主动重新检查；失败保留输入可重试，迟到返回不能覆盖后续编辑。
